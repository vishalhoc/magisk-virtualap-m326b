🧠 How Cellular Carriers Detect Hotspot / Tethering (Technical Breakdown)
Vector 1 IP TTL (Time To Live) & Hop Limit Discrepancy

Standard Android phone packets originate with TTL=64. Windows computers originate with TTL=128. When a PC sends packets through a phone, the phone's Linux kernel decrements TTL by 1, resulting in TTL=127 arriving at the carrier tower. Seeing packets with TTL 127 or odd decrements immediately flags tethered traffic.

Vector 2 Dedicated DUN APN & Carrier Entitlement Check

Android's TetheringManager is programmed by mobile carriers to route hotspot traffic through a dedicated APN (type=dun) or query a provisioning server. Our module permanently disables tether_dun_required and clears entitlement checks so all tethering uses regular mobile data.

Vector 3 TCP MSS & SYN Packet Profiling (TCP Fingerprinting)

Windows, macOS, and Linux have distinct TCP SYN packet signatures (Window Scale, Selective ACKs, and default MTU/MSS sizes). By clamping MSS to PMTU (iptables -t mangle -j TCPMSS --clamp-mss-to-pmtu), packets are reshaped to standard mobile MTU boundaries.

Vector 4 DNS Inspection & Deep Packet Inspection (DPI)

When a PC connects, it queries desktop-specific domains (e.g., windowsupdate.com, steamcommunity.com, apple.com). If queries go to the carrier's DNS servers, carrier DPI logs these queries as proof of PC tethering. Our module transparently redirects all port 53 DNS queries to encrypted/neutral 1.1.1.1.

Vector 5 IPv6 SLAAC & EUI-64 MAC Leakage

IPv6 global addresses often encode the connected device's MAC address (EUI-64) or obtain separate IPv6 global SLAAC addresses under the subscriber's prefix. Dropping IPv6 forwarding forces all client traffic over single-IP IPv4 NAT, cloaking device identity.
